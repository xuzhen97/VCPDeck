# ADR-0056：功能条目作为声明式契约，与 Client 自报能力分离

- 状态：Accepted
- 日期：2026-10-18
- 决策者：项目维护者
- 关联：[ADR-0005](./0005-shared-contracts-and-communication-channels.md)、[ADR-0009](./0009-trusted-operator-security-domain.md)、[ADR-0053](./0053-retire-p2p-tunnel-and-browser-remote-desktop.md)、[ADR-0055](./0055-client-operator-annotations.md)、[`docs/design/feature-registry.md`](../design/feature-registry.md)、[`docs/integration-guide.md`](../integration-guide.md)

## 背景

远程能力正在通过基础工具被逐个造在目标机器上，但**能力建成之后的语义没有归属**：

- `MachineRegister.capabilities` 只有 `exec`、`file.*`、`terminal`、`frp` 这类技术原语，表达不了"这台机器能出图 / 能截图"；
- `Job` 只记录运行过什么命令和状态，不记录"那意味着什么、怎么复用、前提是什么"；
- 真实知识分散在人脑、Agent 长期记忆和目标机上的 `SOP.md` 里。典型两例：某台机器上的截图工具（产出是该机器自身的状态），以及 ComfyUI 出图 / 视频生成（产出是新造的东西，换台机器做语义不变）。

结果是每次复用都要重新读文档、重新试探，且无法回答"它现在还有没有效"。

ADR-0055 已经为"Client 自己无法可靠上报、但对远程操作很关键的事实"建立了模型：Server 持有、操作者声明、注册不得覆盖。功能条目属于同一类数据，但比说明性注解更强——它需要**调用契约**（怎么调、输入、输出）和**有效性证据**。

当前系统是可信操作者单信任域（ADR-0009），任意有效业务身份都等价于远程操作员。本决策不得因此引入新的授权维度，也不得让 Server 变成访问内网的探测跳板。

## 决策

1. **权威分离**：功能条目由 Server 持有，属于操作者/Agent 声明；Client 不上报、不感知、不写入，注册、心跳、重连和改名都不得覆盖。条目与 `capabilities` 是两套不同事实，禁止互相推导。
2. **归属与语义分类**：条目绑定一台 host `Client`，并用 `scope` 表达"能否换机器做"：
   - `generic`：产出是新建的东西，与执行机器语义无关，可跨任务复用，多台 host 互为备援；
   - `machine`：产出就是该机器自身的状态，只对该机器有语义，不得换机器顶替。
   **不建模网络可达性**。FRP 负责打通链路，`annotations.publicAddress` 负责声明网络事实；功能条目再记一次会形成三处互相打架的副本。`scope` 是语义分类，不参与授权，也不代表可达性。
3. **意图与证据分离**：
   - `status`（`draft` / `active` / `retired`）是**意图**；
   - `lastVerifiedAt` / `lastVerifiedOk` / `lastVerifyEvidence` / `verifiedVia` 是**证据**；
   - **`active` 只能由一次成功的验证产生**，REST、CLI、UI 任何入口都不得手写 `active`；
   - 验证失败**自动降级为 `draft`**（`retired` 不因验证被复活）。因此系统里不存在"`active` 但最近一次验证失败"的中间态。
   - `active` 只表示声明，不证明此刻可用；是否仍然有效必须结合证据年龄（新鲜度）判断。
4. **验证归调用方**：验证由能落到执行面的调用方（CLI / Agent）执行，Server 只记录结果、耗时、证据摘要与来源（`via`）。Server 与浏览器都不代替验证：Server 代抓任意存储 URL 等于自建 SSRF 面，浏览器受 CORS 约束无法访问内网服务。v1 不做后台定时探测；新鲜度在读取时按固定阈值计算，只暴露证据年龄，不隐式改变状态。
5. **不代理执行**：本次不新增 `feature.run` 之类的 Job 类型。`command` 型调用复用既有 `jobs run` 与 exec Job，`http` 型由调用方直连；VCPDeck 只承担目录与账本职责。
6. **内容边界**：条目只收稳定、决策相关、非秘密的信息。禁止保存密码、Token、Cookie 等凭据；URL 拒绝 userinfo（`user:pass@`）与控制字符；命令、URL、说明文本设长度上限。命令文本与远端回传的证据摘要按敏感正文对待。
7. **兼容**：新增独立表、新 REST 域和新前端入口，不触碰 Client、注册协议和既有字段，不提升协议版本；旧 Server/旧 Client 组合互不影响。回滚只需移除路由、表和前端入口；已经发生的远端副作用（验证时真实执行过的命令）不回滚。
8. **v1 明确不做**：硬删除条目、条目版本历史、标签与全文检索、按身份隔离、后台探测、UI 侧验证入口。出现真实需求时另立决策，不在本决策上静默扩张。

## 候选方案

- **放进 `capabilityDetails` 由 Client 上报**：实现最直接，但注册会覆盖，且 Client 并不知道业务语义与调用契约；也等于允许 Client 冒充操作者描述能力。
- **塞进 `annotations` 自由文本**：不需要新表，但无法表达结构化的调用契约与输入输出，无法按 scope 检索，也无法承载"证据"，最终会腐化成第二文档库。
- **新增 `feature.run` Job 类型由 VCPDeck 代理执行**：复用最省心，但要引入第二套产物回传、取消、审计与权限语义，与现有 `jobs run` 重复；对 `http` 型还要在 Server 侧发起外部请求，扩大边界。
- **Server 代验证 + UI「验证」按钮**：体验最好，但 Server 抓取存储 URL 构成 SSRF 面，浏览器又受 CORS 限制，最终会分裂成"命令走 Server、HTTP 走服务端代理"两套语义。
- **用 `tags` 或 `reachability` 建模可达性与分类**：标签在 ADR-0055 已被推迟且无法表达契约；可达性会与 FRP 映射和 `annotations` 形成三份会漂移的事实。
- **只做指针式笔记（记录脚本/SOP 位置）**：成本最低，但 Agent 每次仍需重读文档，也无法判定"还有没有效"，等于不做沉淀。

## 后果

正面：

- Agent 有了稳定的发现入口：先查再动手，避免重复造同一能力；
- 调用契约与有效性证据集中一处，复用时可核验，而不是依赖个人记忆；
- 与 `capabilities`、`annotations`、FRP 各自职责清晰，不产生互相覆盖的副本；
- `active` 的结构性约束让"声称可用"与"确实可用"在数据上不可混淆；
- 不触碰 Client，兼容与回滚成本低。

负面与风险：

- 证据的可信度依赖调用方诚实执行验证，Server 不亲测；多身份环境无法区分是谁跑的（v1 只记录时间与来源）；
- 无后台探测意味着条目不会自动变红或变绿，必须有人验证才会刷新；
- UI 无法验证，操作者需要 CLI 才能刷新证据；
- 条目仍可能腐化：调用方式变了而条目没改，`fresh` 也可能指向错误契约；
- 命令文本、内网 URL 与远端输出会进入数据库，扩大敏感数据面，需要长度上限与展示脱敏；
- 若未来出现"条目直接被调度执行"的诉求，需要评估产物回传与权限边界，不能在本决策上直接打补丁。

安全与数据影响：

- 写入权限沿用当前单信任域模型（ADR-0009），任意有效身份可写；`createdByName` 只作审计，不是授权边界；
- `command` 型验证继承 host 的 OS 账户权限，不是沙箱；
- 不在普通日志中回显完整命令、URL 与证据正文。

## 验证与退出条件

实现完成后必须验证：

- `active` 无法通过 REST、CLI、UI 手写产生，只有验证上报可以；
- 验证失败自动降级为 `draft`，`retired` 不被验证复活；
- 同一 `slug` 可存在于多台 host，按 `slug` 查询在存在歧义时 fail closed，不猜测；
- Client 侧无任何改动，旧 Client 注册、心跳与 Job 全链路不回归；
- URL 含 userinfo 或控制字符在 shared 层被拒绝；
- 新鲜度阈值只在 shared 中定义一处，读取时计算，不落库、不后台写入。

出现以下情况时应创建新 ADR supersede 或扩展本决策：

- 需要由 VCPDeck 直接执行功能（产物回传、取消、审计、权限边界）；
- 需要 Server 侧或后台的自动探测与巡检；
- 需要条目版本历史、按身份隔离或跨系统消费（例如导出给外部调度器）；
- `annotations` 与功能条目出现字段重叠或同步诉求。
