# ADR-0038：共享 PSK 下的 Git SSH 分发仅以 Client ID 作运维目标

- 状态：Accepted
- 日期：2026-09-30
- 决策者：项目维护者
- 关联：[ADR-0037](./0037-server-managed-git-ssh-key-distribution.md)、[ADR-0009](./0009-trusted-operator-security-domain.md)、[`docs/security.md`](../security.md)
- 取代范围：仅取代 ADR-0037 决策 6 中「无法保证分发目标边界则暂停分发」的门槛，并限定决策 2 的「认证、绑定」仅为共享 PSK + 当前注册 Client ID 的运维关联，**不代表每机认证**；ADR-0037 其余决策继续有效。

## 背景

现有 `/client` 连接只校验所有 Client 共用的 PSK；注册时 Client 自报 ID，同一 ID 可有多个连接。拥有 PSK 的另一台机器能够冒用已选 Client ID，接收原本发往该 ID 的共享 Git 私钥。ADR-0037 决策 6 原要求无法证明目标机器身份时暂停分发，这意味着必须先建设每机身份认证。操作者在少量受信机器的部署前提下，选择优先减少配置步骤，明确接受 PSK 泄露或受信机器失陷可能导致整套 Git 私钥泄露的风险。

## 决策

1. Git SSH 密钥分发第一阶段沿用共享 PSK，不以每机身份认证作为上线前置条件。Server 依据已注册的 Client ID、协议能力和期望绑定选择发送对象；选机只控制正常运维流程，不是机器级访问控制或私钥防冒领措施。不得把 Client 自报 ID 或重复连接检测宣传为真实机器身份校验。
2. 下发及安装回报仍须匹配当前注册 socket、能力和版本；对重复连接、断开、重连与过期回报按 socket 租约及版本对账，错误状态不可显示为已安装或已清理。这些措施只维护运维状态一致性，不能防止持有 PSK 的攻击者冒用已选 ID；管理面和安全文档须明示此边界。
3. 任一持有 PSK 的机器失陷、PSK 泄漏或共享私钥疑似泄漏，按**整套 Git 私钥失陷**处置：在 Git 服务撤销旧公钥，生成新密钥并人工配置新公钥，仅向仍受信的机器重新分发，同时轮换 PSK。某台 Client 的本地清理确认、离线待清理或从分发列表移除，均不是 Git 服务侧可靠撤销。
4. ADR-0037 的 Server 加密保存、Client 受限持久化、仅 VCPDeck Job/Terminal/Pi 继承、TOFU、严格协议与 Git 服务侧换钥义务不变。现有 Job/Terminal/Pi 与 Client OS 同账户进程仍可读取可用私钥，不提供同账户隔离或多租户保护。

## 候选方案

- **先实施每机身份认证，再分发**：可为选机建立可验证的身份边界，但增加发放、现有机器配对、轮换和恢复流程；当前受信部署阶段不采用。
- **继续执行 ADR-0037 的暂停门槛**：避免 PSK 冒领风险，但无法在现有架构下实现要求的集中分发；操作者明确接受该风险后不采用。
- **只拒绝重复 Client ID**：能减少误连接，但持有 PSK 者可在原 Client 离线时抢先注册；不构成每机认证。

## 后果

- 可在现有共享 PSK 部署下推进一次配置、多机器使用 Git SSH 的目标；代价是「选定机器」不提供保密或单机安全撤销保证，一台受信机器或 PSK 失陷可能波及全部共享 Git 权限。
- 下发状态必须谨慎展示为运维观察值，不表述为身份验证或私钥未泄漏证明；生产仍需保护 PSK、私钥文件及 HTTPS/WSS 通道。
- 一旦部署范围包括不受信机器、需要可验证的机器级授权或独立撤销、或要缩小 PSK 泄漏的影响面，须重新设计每机身份与 Git 凭据模型，并用新 ADR 取代本取舍。

## 验证与退出条件

用持有共享 PSK 的模拟 Client 自报已选 ID 验证冒领风险确实存在且文档/UI 不误称选机为安全边界；测试重复 socket、重连、旧版本回报不得错误收敛状态；测试泄漏处置指引涵盖 Git 服务撤销、整体换钥及 PSK 轮换。以上测试不应声称已阻止持有 PSK 的攻击者领取私钥。
