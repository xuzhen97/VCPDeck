# ADR-0051：客户端补更采用分级有限重试与周期对账

- 状态：Accepted
- 日期：2026-10-14
- 决策者：项目维护者
- 实施状态：尚未实施；设计批准不代表该行为已交付。
- 关联：[ADR-0003](./0003-separate-launcher-for-updates.md)、[ADR-0021](./0021-frp-dashboard-confirmed-mapping-lifecycle.md)、[ADR-0022](./0022-release-artifact-and-launcher-retention.md)、[ADR-0016](./0016-release-archive-storage-provider.md)
- 关系：不替代任何既有 ADR；延续 ADR-0021 的重试所有权原则并补足其未覆盖的驱动力缺口。

## 背景

客户端补更存在一处会导致永久掉队的行为：一台客户端在某次发布中被标记为更新失败后，之后不再被纳入任何补更，既无重试也无豁免，且没有任何入口能主动发现它。

生产证据有两例。一次发布中全部十台客户端同时失败，事后脱身的方式是紧接着又发布了一个版本，而非依赖自愈；另一台客户端在后续发布中再次失败，此后长期停留在旧版本，而它在此期间心跳正常、持续在线——由于补更只由「客户端重连注册」触发，它从不再次注册，因而永远不会被自动重试。Server 重启也无效：启动恢复只处理进行中的发布，已完成发布中的失败记录不被触碰。

因此当前行为存在两个独立缺陷：失败记录被一视同仁地永久排除，以及重试驱动力完全依赖客户端重连事件。

## 决策

1. **失败分级**：客户端更新失败分为瞬时与永久两类。失败类别由写入失败的代码路径直接指定，**不解析已脱敏的原因文案**；文案调整不得改变重试行为。构件缺失与平台不支持属永久失败，任何情况下都不重试；等待重连注册超时与注册版本不符属瞬时失败。
2. **重试判定单一来源**：是否可重试由一个判定入口决定，所有补更触发点共用该判定，不得各自实现条件。判定须考虑失败类别、已尝试次数与距上次失败的时间。
3. **有限重试**：Server 是客户端补更的唯一重试所有者，延续 ADR-0021 已确立的原则。瞬时失败按递增退避重试并设次数上限；上限耗尽后停止自动重试并转为需人工处理，**不自动升级为错误终局，也不无限重试**。单次重试会产生一次完整构件下载，次数上限同时是带宽与磁盘开销的约束。
4. **周期对账作为第二驱动力**：补更不再仅由客户端重连触发。Server 周期性对账当前目标版本下落后且可重试的客户端并触发补更，使「持续在线但已失败」的客户端能够自愈。周期对账与注册钩子必须共用同一互斥入口，**不得并发开启第二条更新循环**，避免 ADR-0021 所否决的嵌套或乘法重试。
5. **归档与目标约束不变**：只有具备目标平台构件的版本才作为补更目标；已清理归档不得参与下载、编排或补更（ADR-0022）；补更与重试沿用既有的直链按需换取规则（ADR-0016）。
6. **人工兜底与可见性**：提供显式的人工重试入口，作为自动重试耗尽后的唯一兜底。人工重试忽略退避与次数上限，但仍记录尝试次数，并仍然拒绝永久失败以避免重复必然失败的动作。CLI 必须能展示逐台更新明细并标出落后于当前目标版本的机器，使掉队可被发现；这些判定以 Server 与客户端上报的权威状态为准，CLI 不做本地推断。

## 候选方案

- **维持现状，仅在客户端注册时重试**：实现最小，但对持续在线的失败客户端完全无效，无法解决已观察到的生产问题，不采用。
- **不限次数持续重试直到成功**：自愈能力最强，但故障未排除时会反复触发完整构件下载，形成带宽与磁盘放大，且无法终止，不采用。
- **解析原因文案判断类别**：不改动契约，但文案调整会静默改变重试行为，长期不可控，不采用。
- **只提供人工重试、不做自动重试**：完全可控，但依赖操作者主动发现与介入，重复了当前「掉队不可见」的问题，不采用。
- **分级有限重试 + 周期对账 + 人工兜底**：自动解决瞬时失败，人工兜底永久与耗尽场景，全过程可观测，采用。

## 后果

正面：客户端不再因单次发布失败而永久掉队；永久失败不再浪费重试资源；掉队机器在 CLI 侧可见；重试所有权与互斥约束延续既有决策，不产生多重触发源。

成本与约束：引入一个周期性运行组件与一项策略判定；失败记录需要携带类别与尝试次数；CLI 新增明细展示与人工重试入口。周期与退避参数需在实施后依据真实数据复核，不能仅凭设计固化。

运维：重试耗尽的客户端需要人工介入；人工重试属写操作，沿用既有身份校验与稳定错误码，不新增凭据路径。周期对账自身异常只记录日志，不得影响 Server 主流程。

## 验证与退出条件

- 失败后未达重试上限的客户端能在退避到期后被重新纳入补更，且不与注册钩子并发开启第二条更新循环。
- 永久失败在任意次数的自动与人工重试下都不被重试。
- 超过上限的瞬时失败停止自动重试并在 CLI 明细中可见。
- 逐台明细不包含未脱敏内容；落后标记以权威版本状态为准。
- 既有发布状态机、Server 自更新流程、客户端协议与其他 CLI 命令行为不变，相关测试与全仓门禁通过。

若未来需要灰度、分组、暂停、批量强制重试，或重试所有权移交给客户端，必须重新评估并另立决策。
