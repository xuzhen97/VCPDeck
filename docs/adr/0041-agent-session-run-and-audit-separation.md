# ADR-0041：Agent Session、Run 与最小审计独立于 Job

- 状态：Accepted（已实现，2026-10-08）
- 日期：2026-10-08
- 决策者：项目维护者
- 替代：ADR-0008；局部替代 ADR-0004 决策第 9 条的 Pi Session 复用 Job 约束
- 关联：[`domain-model.md`](../domain-model.md)、[`protocols.md`](../protocols.md)、[`compatibility.md`](../compatibility.md)、[`remote-pi.md`](../design/remote-pi.md)

## 背景

Agent 会话可以长期使用，不需要用户认定“任务完成”。当前 `agent.session` Job 同时承载会话所有权、当前 Run 状态、人工完成标记和最小审计；其 done 可以重新激活，与普通 Job 的终态不同。仅将 Agent 从 Job 页面隐藏不能消除数据和协议语义的耦合。

ADR-0008 已解决稳定会话身份、独立 runId 和并发隔离问题，但复用 Job 不能保存完整逐轮执行摘要。本次需要独立的会话操作与每轮执行审计，而不是逐工具审计或 Server 对话镜像。

## 决策

1. AgentSession 是独立控制面实体，保存稳定 sessionId、Client、固定 Owner、会话控制配置和最小生命周期元数据。不要求对应 Job 行，不使用 Job done/error/cancelled 表示会话生命周期。
2. 移除会话“完成”语义。归档与恢复只管理会话入口，不删除远端对话、不改变当前 Run 结算；会话可以长期空闲并继续使用。
3. 每次 Prompt 触发独立 AgentRun，以新的 runId 关联 sessionId，覆盖本轮工具执行与扩展等待输入。Run 由权威执行报告自动结算为成功、失败或已中止；终态不重新激活。某轮失败不使整个会话永久失效。
4. AgentRun 保存发起者、可核实的执行时间、状态和安全结果摘要，本身承担每轮执行审计，不另建镜像 Run 状态。会话创建、导入、归档、恢复、删除与执行模式变更等控制面操作使用独立最小审计事件。
5. 删除会话不级联删除 Run 摘要和会话操作历史；审计保留稳定 sessionId 与必要快照，不依赖远端正文存在。审计与控制面变更必须一致；跨网络操作区分请求与已确认结果。
6. Server 保存控制面状态与最小审计；Client 持有 Worker、实际执行资源与 Session 内容。Server 不持久化 Prompt、回复、thinking、图片正文、扩展输入、工具参数或工具输出；本次不引入逐工具审计。
7. 保留固定 Owner、同会话单活跃 Run、同 Client/projectKey 单活跃 Run，以及连接代次与重连对账保护。状态转换、事件、项目锁和结算计时器均绑定精确 sessionId/runId，使用允许源状态的条件更新；旧 Run 不得影响新 Run。
8. 断线不是执行失败，中止请求不是已中止结果。先完成 Client 权威对账再恢复控制；无法恢复时安全结算，不自动重发不确定是否执行的 Prompt。
9. 新 Agent 操作不创建或更新 Job，不参与普通 Job 列表、统计或通用任务控制。Shared、Server、Client、SDK、Frontend、CLI 与 SSE/重连链路统一采用独立会话与 Run 契约；旧 complete 不无声映射为成功或归档。
10. 保持原 sessionId 与远端对话关联，迁移可核实的所有权、配置和元数据，不伪造旧模型未保存的逐轮历史。旧 done 不自动解释为归档或某轮成功，删除预约需单独处理。
11. 使用可审查数据库迁移与显式 Pi 协议版本切换。切换前停止接纳新 Prompt，将旧活跃 Run 按旧协议结算、对账或明确安全终止；不能仅改表后宣称原执行已恢复。新旧不兼容 Pi 协议安全拒绝，不影响普通 Job 能力。
12. 升级前备份，审核切换与回退要求；不假定旧二进制能够读取新模型。当前不引入双写事实源、外部消息队列、新部署组件、并行 Run 或 Owner 转移。

## 候选方案

### 独立 Session、Run 与会话操作审计（采用）

匹配长期会话与有限执行的真实生命周期，使逐轮摘要可查询，并避免把人工整理动作当成执行结算。代价是数据库迁移、协议变更与跨端适配。

### 仅隐藏 Agent Job

界面改动小，但状态、审计和协议继续依赖 Job，无法消除语义冲突，因此不采用。

### 每次 Prompt 创建普通 Job

可复用任务历史，但 Agent 控制与审计仍依赖 Job，且需额外处理长期会话、Owner 与 Run 关系，因此不采用。

## 后果

### 正面

- 长期空闲会话不被解释为未完成任务，无需人工完成。
- 每轮结果独立可查询，失败、中止与会话归档互不混淆。
- Agent 审计不依赖 Job，不复制完整对话或工具正文。
- 保留现有运行安全保护，同时消除专门 Session Job 与普通 Job 的终态冲突。

### 成本与约束

- 需要独立持久化模型、查询入口、数据库迁移和 Pi 跨端协议升级。
- 旧模型不能提供完整 Run 历史，迁移必须据实表达缺失。
- 审计独立保留使删除、引用与备份需显式处理；本决策不新增自动清理策略。
- 活跃执行不能依靠数据库搬迁无缝接管；升级和回退必须验证网络执行状态与数据兼容。
- 本 ADR 已实施：Shared 协议 v4、Server/Client/SDK/CLI/Frontend 与会话/审计持久化均已切换，Current 文档与 CHANGELOG 已同步。
- 本版迁移是 **expand-only**：只新增三张表与一个关系字段，不删除、不改名、不收紧任何既有字段，因此符合 [`compatibility.md` §6](../compatibility.md) 的 expand/migrate/contract 规则。回退只需 Launcher 切回上一版本，旧版本代码继续读写同一数据库，**无需恢复备份**（已用上一版本 schema 对迁移后的库复核 `db push`：仅报告多余表，无任何需新增或修改项）。
- 迁移**刻意不删除**遗留 `agent.session` Job 行与 Job 上不再使用的三个模式列，使回退后旧版本仍能看到原会话；对应的 contract 清理必须放到版本稳定后的后续发布，不随本版进行。

## 验证与退出条件

验证长期空闲不产生 Agent Job、连续 Prompt 使用独立 Run、自动结算、失败后继续、等待输入、中止确认、旧事件隔离、项目互斥、Owner 权限、断线/重连/进程重启对账，以及删除后最小审计仍可查询且不保存正文。

迁移需覆盖旧 idle/done/error、活跃 Run 与删除预约，验证原 sessionId 保留、不伪造历史、新旧 Pi 协议明确拒绝与回退要求。同步 Current 文档、兼容说明与 CHANGELOG 后才声明交付。

若未来需要并行执行、Owner 转移、多人协作、逐工具审计、审计保留策略或多 Server 协调，应另行评估权限、数据权威与运行模型，不通过扩大本决策隐式引入。
