# ADR-0045：中央 Pi 编排与目标机原生 Agent 环境

- 状态：Superseded by ADR-0049
- 日期：2026-10-10
- 决策者：项目维护者
- 实施状态：尚未实施；Accepted 表示长期方向已批准，不表示中央 Pi、原生环境接入或旧体系退役已交付。
- 修订：2026-10-10 —— 维护者决定：平台范围收窄为 Windows + Linux，**不支持 macOS**；并明确“原生配置”指 Agent 应用自身安装与配置，**不是**用户个人主目录配置；运行账户确定为 Client 系统级账户（见决策 2）。

## 背景

既有远程 Pi 体系由 Client 内嵌 SDK，配合 Server Profile、Credential、RuntimeSpec、隔离数据根及随 Release 交付的扩展 Bundle。它承担了模型配置、资源发现、社区扩展依赖、网页交互适配、协议门控和更新回退等多重责任。带原生模块、WASM 或独立 helper 的社区扩展进一步扩大了发布体积与校验成本。

维护者当前需要两种并存的使用方式：人工直接使用目标机原生 Pi/DSH 开发，以及让中央 Pi 或外置 Agent 在同一个长期环境中持续操作并与人交接。人工不应只能向中央 Agent 发任务，也不应依赖模型服务可用才能进入开发环境。

因此选择改变 Agent 运行时的权威边界，而不是继续完善 Client Bundle 或把旧控制体系搬到 Server。运行资源仍在目标机器；VCPDeck 的主要责任变为远程操作、认证、接入和必要的生命周期协调。

## 决策

### 1. Server 中央 Pi 是可选操作者

Server 集成简单的中央 Pi，通过 VCPDeck 既有 Jobs、Files、Terminal 和必要的服务接入能力操作目标机器。远程业务操作携带可追溯的操作者身份并经过 Server 控制面，不引入 Client 到 Client 的直接控制链路。

人工可独立进入远端环境，不需要先发起中央对话，也不依赖中央 Pi 推理、模型凭据或模型服务的可用性。中央 Pi 不因位于 Server 就获得匿名控制权限或默认任意 Server 本地 shell 权限。

不将旧 Profile/Binding/RuntimeSpec/Bundle 体系原样搬到 Server。中央 Pi 的配置、凭据注入、工具集合及对话持久化在其阶段设计中单独确认。

### 2. 目标机原生 Agent 拥有其运行时与配置

Pi/DSH 独立安装，使用**自身**的原生配置、插件、模型凭据、项目资源和对话历史。它们不是 Client Release 的组成部分，不随 Client 更新自动覆盖或升级。

**“原生”的准确定义：** 指 Agent 应用自己的安装与配置（settings、插件、凭据、会话历史），**不是**人类用户在个人主目录下已经维护的那一套。VCPDeck 将 Agent 重新安装/配置到 Client 的系统级账户下，这一点已被维护者明确接受；因此“人工直接使用目标机 Pi/DSH”指的是接入**该账户下那套 VCPDeck 管理的环境**，而不是接管用户的个人环境。

VCPDeck 可以通过显式远程操作安装、配置或启动环境，但不因此成为远端模型和插件的统一配置权威，不建立隐式资源同步或第二套 Agent 包管理器。

运行账户确定为 **Client 系统级账户**（Windows `NT AUTHORITY\SYSTEM`、Linux root 等价专用账户，沿用 [ADR-0027](./0027-system-level-client-installation-and-clean-migration.md)）。不做跨账户启动、不做每用户宿主、不实现用户凭据代持；本决策取代早期草稿中“账户待定/可能跨账户”的表述。

后果必须如实记录：Agent 在系统级账户下运行等于**提权面最大化**。任意有效业务身份、PSK 泄漏、命令注入、提示词注入，以及项目内 `.pi/extensions` 可执行代码（见 [ADR-0043](./0043-project-local-pi-resources-unconditional-trust.md)），都会直接升级为整机最高权限代码执行。这不是沙箱，且不得在任何界面或文档中淡化。

### 3. Client 退出专用 Agent 运行时管理

Client 保留命令、文件、终端与网络接入等通用基础能力。新路径不内嵌 Pi SDK，不负责 Agent 模型策略、插件发现、对话内容解释或社区扩展 Bundle 分发。

跨 Client 重启保活及 PTY 重新接入需要独立的通用会话宿主，其生命周期、部署、认证和兼容边界另立 ADR。本 ADR 不选择保活依赖、通信协议、包结构或跨平台实现，也不将新增宿主描述为已经交付。

### 4. 人和 Agent 共用原生界面与会话

平台范围为 **Windows 和 Linux**；macOS 不支持，不要求、不验收、不预留实现分叉。

Pi 使用原生 TUI，DSH 使用原生 Web；不重做统一远端聊天界面，不强行以同一种输入协议替代两者。

首期只管理从 VCPDeck 启动的实例，不发现或接管本地/SSH 另行启动的活跃实例。区分环境实例、Agent 对话和接入连接：一个 DSH Web 服务可包含多个对话，自动操作必须确认目标对话；使用同一套配置不等于进入同一个活跃会话。

支持人工直接开发、显式委托和接管。接管停止自动输入，不自动取消远端 Agent 已经执行的任务；再次委托前重新观察现场，不重放接管前的待执行输入。

Pi 受管理终端输入可以强制单写。DSH 原生网页首期协调受管理自动操作者，不宣称存在覆盖所有人工页面或外部 API 的全局输入锁。停止自动输入、取消应用当前执行、停止环境和删除历史是不同操作。

### 5. 明确正文与凭据的数据边界

远端原生历史由目标机 Agent 管理，Server 不默认镜像全部远端对话或终端正文。中央 Pi 的对话归 Server 中央运行时；它阅读的远端文件、屏幕和对话可能进入中央上下文、模型请求或会话存储，不能笼统沿用“Server 永不保存远端正文”的承诺。

中央会话不是远端历史的第二事实来源。中央内容的保留、删除和凭据安全需单独细化；不得将模型凭据、网页 token、终端正文或原始外部错误写入普通日志和最小审计。

保留 VCPDeck 认证及 DSH 原生认证/请求信任检查，不以关闭 Host/Origin 校验、裸露 token 或开放无认证端口作为网页接入方案。

### 6. 替代路径验收后再退役旧体系

先验证人工原生接入与保活，再完成中央 Pi 和自动操控，最后退役旧 Client SDK、Bundle 构建/交付、专用控制协议和不再需要的页面。

退役前盘点旧活跃执行、配置、凭据、会话和审计，并明确升级与回退边界。保留旧历史与最小审计，不自动删除或导入，不伪造旧 Session/Run 与新原生实例的关联。不能从 TUI 猜测工具执行并冒充旧 AgentRun 审计。

新旧能力不兼容时明确拒绝，不静默回退旧 Pi 模式。移除执行代码不等于授权删除持久化数据；数据库清理、凭据迁移和真实任务停止需要另行审核。

## 与既有决策的适用关系

本 ADR 是新架构的长期方向，不修改旧运行时的当前行为，也不批量变更旧 ADR 的状态：

- **ADR-0007**：保留远端资源驻留目标机器、界面不是事实来源及 Server 最小持久化原则；中央 Pi 对话适用本 ADR 的正文边界。Client 不再独占 PTY/Worker 生命周期的具体变化，由独立会话宿主 ADR 明确。
- **ADR-0041**：保留长期交互独立于普通 Job、断线不等于失败、审计据实保留的原则；其旧 AgentSession/Run、Owner 和 Worker 契约不自动套用到原生环境。
- **ADR-0036、ADR-0042、ADR-0043、ADR-0044**：其中 Client 内嵌 SDK、Bundle 交付及隔离资源规则适用于尚未退役的旧路径，不作为新原生环境的约束。新方向不继续推进 ADR-0044 目录树交付；正式退役时逐项明确替代范围与状态，不改写历史结论。
- **ADR-0029、ADR-0030**：当前文件与索引状态为 Proposed，其集中配置与隔离 Bundle 方向不用于新路径；不能将这些提案误称为 Accepted。

实施切换必须同步相关 Current 文档、兼容说明、部署/运维和 CHANGELOG；在切换完成前，它们仍描述旧代码，不将本 ADR 写成现有能力。

## 候选方案

1. **继续 Client 内嵌 Pi 与统一 Bundle**：可固定交付组合，但持续承担社区依赖、完整性校验及网页适配成本，也不满足直接使用目标机原生环境的目标；不采用为后续方向。
2. **把旧 Pi 控制体系完整搬到 Server**：仅移动复杂度，仍不能自然支持原生远端 TUI/Web 和人工独立使用；不采用。
3. **统一 Pi RPC、DSH API 或重做远端聊天 UI**：结构化控制更精确，但增加 Agent 特定协议及扩展 UI 兼容责任，且不能直接证明与原生界面共用同一活跃实例；首期不采用。
4. **每次任务启动一次性 Agent**：容易复用普通 Job，但不能满足长期会话和人机交接；不采用。
5. **简单中央 Pi 加通用接入，目标机 Agent 原生运行**：采用，优先保留原生能力并减少 VCPDeck 自有 Agent 管理面。

## 后果

正面：人工与自动操作使用相同原生环境；Client 与第三方模型/插件解耦；避免持续扩大 Bundle 和统一聊天渲染层；中央 Pi 可以复用已有机器操作能力。

成本与限制：不同机器的 Agent 版本、插件和凭据可能不同，不能再承诺同一 Client Release 的远端 Agent 能力一致。浏览器自动化、PTY 观察和交接仍需验证；DSH 网页接入涉及完整 HTTP/WebSocket 和双层认证，通用 TCP 隧道不等于完成代理。运行账户、中央正文持久化以及保活组件带来独立安全和运维责任。

支持目标为 **Windows 与 Linux**。macOS 已明确移出范围：不新增 darwin 交付变体，不实现 LaunchAgent 守护，也不以“Agent 官方支持 macOS”为由声称支持。跨 Client 重启保活不是跨机器重启继续原工具执行。

## 验证与退出条件

- 中央 Pi 不可用时，人工仍可通过认证入口完整使用原生 Pi TUI 与 DSH Web。
- Windows 与 Linux 分别提供真实接入与恢复结果；独立宿主的跨 Client 重启保活按其 ADR 单独验收。
- 远端环境使用 Client 系统级账户与项目资源；Client 更新不覆盖 Agent 自身配置、插件、凭据与历史。
- 人和受管理 Agent 可以操作同一活跃实例/对话；接管后旧自动输入停止，再次委托重新观察，不重复提交结果不明的任务。
- DSH 接入保留原生认证，HTTP、静态资源、Cookie、Origin/Host 与 WebSocket 均通过固定版本验收，不宣称全局输入锁。
- Windows、Linux 分别提供真实接入与恢复结果；独立宿主的跨 Client 重启保活按其 ADR 单独验收，未验证平台明确标注。
- 旧体系仅在替代路径验收后退役；历史与审计保留、混合版本拒绝、数据兼容及回退得到核验。

若未来要求统一模型/插件治理、强制覆盖 DSH 所有入口的写锁、结构化逐工具审计、跨机器活跃会话迁移或服务端永久镜像远端正文，应另立 ADR，不能以完善接入为名隐式扩大本决策。
