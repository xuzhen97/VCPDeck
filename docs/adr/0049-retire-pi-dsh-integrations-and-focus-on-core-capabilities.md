# ADR-0049：退出 Pi／DSH 专用集成，聚焦基础能力

- 状态：Accepted
- 日期：2026-10-12
- 决策者：项目维护者
- 实施状态：尚未实施；批准退役方向不表示代码、页面或发布构件已删除。
- 替代：ADR-0045、ADR-0046、ADR-0047、ADR-0048，以及下方列明的 Pi 专用决策。
- 关联：[ADR-0001](./0001-control-plane-and-outbound-clients.md)、[ADR-0004](./0004-typed-job-kernel.md)、[ADR-0007](./0007-client-owned-interactive-runtime.md)、[ADR-0009](./0009-trusted-operator-security-domain.md)、[ADR-0020](./0020-cli-dataplane-namespace.md)、[ADR-0037](./0037-server-managed-git-ssh-key-distribution.md)

## 背景

Pi 专用运行时、资源交付、模型与凭据管理、会话编排和网页适配使 VCPDeck 承担过重的 Agent 生态维护责任。继续迁移到 Server 或接入目标机原生 Pi／DSH，仍会保留专用协议、运行组件与界面复杂度。

维护者决定先完善基础功能，当前只完成一次完整的能力精简。需要明确：这是退出专用集成，而非继续 ADR-0048 的功能迁移；删除运行能力也不等于销毁历史数据或卸载用户程序。

## 决策

1. **退出全部 Pi／DSH 专用集成**：删除聊天、会话与 Run 编排、历史导入与投影、模型／凭据／Profile、工具策略、扩展交互、SDK／Worker、Bundle、探测和安装适配，以及 DSH 专用启动与代理。专用 Shared 契约、Server／Client 接线、SDK／CLI 调用面、依赖和发布构件同步退出。
2. **退役新增 session-host**：删除该运行组件及其管理、桥接、登记与审计运行链路。不将它改造为新通用宿主以保留前期成果；现有 Terminal 继续使用自己的 Session／PTY 链路。
3. **不建设替代 Agent 体系**：不把旧 Pi 功能移入 Server，不新增 RPC 适配器、中央 Pi、DSH 网页适配或专用 Agent 平台。
4. **保留基础能力与授权边界**：机器、Typed Job、命令／脚本、文件、Terminal、FRP、Storage、身份、Launcher、发布更新及现有通用网络能力不因退役而移除。通用 CLI／SDK 和既有通用调用入口保留；外部 Agent 能调用它们，不构成删除理由，也不构成新增适配面的授权。
5. **页面同步做功能减法**：移除 Agent／聊天路由、专用导航、机器详情入口和设置，不保留空页面或替代聊天占位。本次不重做整体视觉设计，也不夹带基础功能扩建。
6. **历史数据非破坏性保留**：不清空业务表、不重写或删除迁移历史，不引入自动清理，不卸载或修改目标机已有的 Pi／DSH、原生配置及会话。必要的退役存储定义可保留，但不为其保留运行服务或业务入口。物理数据删除需要独立的备份、清理设计与维护者授权。
7. **明确能力删除与兼容成本**：新版本不再宣称专用能力，不提供伪成功接口或静默降级为 shell 的兼容实现。跨版本接入必须按既有协议策略安全处理，必要时采用协调升级或版本门控；不能在未验证时承诺旧 Pi 调用方兼容。通用 Terminal／Job 仍可执行用户明确指定的外部程序，但不提供 Pi／DSH 识别或专用投影。

## 与既有决策的关系

- **整体替代**：ADR-0034、0035、0036、0039、0040、0041、0043、0045、0046、0047、0048。其 Pi／DSH 运行体系不再作为实施目标；ADR-0036 中与 Pi 能力门控绑定的 shell 策略随专用体系退役，基础命令与 Terminal 的既有 shell 实现不据此删除。
- **未采纳提案**：ADR-0031、0032 改为 Rejected，显式导入与渲染层移植不再推进。
- **保留历史替代链**：ADR-0008、0033、0042、0044 已被旧 ADR 替代，ADR-0029、0030 已被拒绝；保持原历史状态，其后继决策再由本 ADR 退役，不复活旧方向。
- **局部退出、基础条款继续有效**：ADR-0007 的 Pi 条款退出，Terminal 与适用的共同原则保留；ADR-0020 的 Pi 调用范围退出，Terminal 数据面规则保留；ADR-0037 的 Pi 消费路径退出，共享 Git SSH 密钥及 Job／Terminal 消费规则保留。ADR-0038 的分发安全约束不变。
- **不恢复 Pi Session Job**：ADR-0041 的业务运行能力退役不恢复 ADR-0004 第 9 条或 ADR-0008 的 Pi Session 复用 Job 方案。Typed Job 内核仍有效，旧数据不因此自动销毁。

旧正文保留为历史结论，只更新状态与后续适用范围。实现期间 Current 文档仍以代码为准；退役落地时同步更新 README、架构、协议、兼容、部署与运维说明及 CHANGELOG，不将方向批准描述成已完成。

## 候选方案

- **继续 Client 内嵌 Pi**：保留最重的运行时与发布耦合，不采用。
- **按 ADR-0048 搬到 Server 并驱动原生 Pi／DSH**：可重新分配职责，但仍需维护专用协议、会话、凭据和界面，不满足本次退出目标，不采用。
- **仅隐藏页面或关闭开关**：后台代码、依赖与维护责任仍在，不构成完整精简，不采用。
- **完整退出专用集成，保留基础能力**：采用；共享实现按实际调用方处理，不按名称机械删除。

## 后果

正面：产品边界清晰，Client／Server／前端与 Release 不再随 Agent 生态变化承担专用适配成本；精力回归基础操作稳定性。

成本：既有 Pi／DSH 业务入口与调用方不再可用；历史数据虽保留，但不再提供专用访问界面。能力删除需要全链路引用盘点、版本兼容说明与基础功能回归，不能用目录删除代替验证。

安全与运维：基础身份校验、输入校验与脱敏规则不变。升级沿用既有停机与资源释放机制，不扫描或杀死用户自行启动的外部程序；旧专用进程的残留风险须如实说明。

## 验证与退出条件

- 专用运行接线、接口、能力声明、页面入口、依赖与发布构件均退出，且无悬空引用。历史 ADR、迁移和必要退役存储定义中的字样允许保留，须能解释用途。
- Server／Client 启动、重连及机器状态正常；Job、文件、Terminal、FRP、Storage、身份与发布更新回归通过。
- 类型检查、相关测试、构建、lint、差异检查及代码图影响复核完成；未进行的浏览器或 Windows／Linux 实机验收明确报告。
- 不发生未授权的数据清理、外部程序卸载、main 改动或发布。

未来重新引入任何专用 Agent 管理、聊天或运行适配，必须重新评估成本并另立 ADR，不以本 ADR 保留的通用能力或历史代码为自动授权。
