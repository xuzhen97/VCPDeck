# ADR-0042：标准 Pi 社区扩展随 Client Release 统一交付

- 状态：Superseded by ADR-0048（2026-10-11：社区扩展不再随 Client Release 统一交付）
- 日期：2026-10-10
- 决策者：项目维护者
- 实施状态：已实施（资源选择与统一构建、社区扩展随 Release 交付、发布布局验收与 `pnpm test:pi-resources` 门禁均已落地）。
- 关联：[ADR-0036](./0036-pi-sdk-single-file-and-shell-capability.md)、[ADR-0039](./0039-pi-two-mode-execution.md)、[ADR-0040](./0040-pi-extension-web-interaction.md)、[`remote-pi-control-plane.md`](../../docs/archive/design/remote-pi-control-plane.md)

## 背景

VCPDeck 已通过官方 Pi SDK 加载受信扩展，并由宿主将部分标准交互投影到网页。现有资源随 Client Release 交付，但社区包接入仍需统一构建入口与兼容验收规则。

维护者希望直接复用社区扩展，减少专有实现与维护成本，同时避免每台 Client 独立安装导致版本和能力漂移。标准扩展格式不等于任意终端交互都能在网页运行，统一发布也不等于不同操作系统的执行条件完全相同。

## 决策

1. **官方 Pi 是扩展作者接口的标准。** 使用所锁定 SDK 版本的官方 ExtensionAPI、默认导出工厂、事件、工具和命令注册机制；社区源码尽量原样复用。包资源发现优先复用官方 Pi Package 声明、约定目录与公开解析能力，不建立要求社区作者使用的 VCPDeck 专用注册接口，不 fork 或 patch SDK。自有扩展遵循同一标准，控制面与网页适配留在宿主侧。
2. **社区扩展及运行依赖在构建期准备，随 Client Release 固定版本交付。** 来源使用固定版本或不可变引用，审查来源、依赖与许可并保留必要许可信息。dev 与正式发布使用同一集中选择输入生成 Bundle，不为每个扩展维护多处手写入口清单。Client 启动、会话建立及命令执行时不安装包或拉取代码。
3. **沿用受信资源与控制面边界。** Client 校验属于自身 Release 的 Bundle，Server 只选择资源 ID 并通过版本与资源能力门控运行；不下发社区可执行源码，不读取用户原生 Pi 资源，不自动加载项目扩展。所有运行时可加载的社区代码、依赖及必要资源必须处于可信发布和完整性校验范围；现有布局无法可靠覆盖时先重新评估设计，不绕过校验交付。
4. **一致性指同一 Release 的交付集合一致。** 扩展来源、版本、依赖选择和资源清单一致；必要的平台构件差异不得悄悄省略宣称提供的扩展。不同 Release 的能力差异由 Server 门控，缺失所需资源时明确拒绝而非少加载。Profile 可显式选择不同启用集合；平台或外部程序条件必须明确说明，不将其宣称为无条件等价能力。
5. **标准格式兼容与网页功能兼容分别验收。** 沿用 ADR-0040 的有限网页交互和宿主敏感操作边界，不模拟任意 TUI、终端 renderer、主题或快捷键，不顺带开放 Session 替换与 Runtime reload。硬依赖 TUI 且无非终端降级的扩展不列入兼容集合。包内 Skills、Prompt 模板及主题不因纳入包而自动开放运行时加载。

本 ADR 不改变 ADR-0036 的 SDK 单文件发布选择、ADR-0039 的执行模式或 ADR-0040 的网页边界，也不改变其他 Proposed ADR 的状态。

## 候选方案

- **逐台 Client 动态安装 npm/git 包**：更灵活，但产生版本漂移、独立供应链与回滚状态，违背统一交付目标；不采用。
- **将社区扩展改写为 VCPDeck 专用插件**：可定制网页语义，但增加迁移和追随社区更新的成本；不采用，适配留在宿主。
- **逐扩展手写发布与开发资源清单**：初期直接，但容易清单漂移和重复维护；采用集中构建输入及标准包声明替代。
- **完整模拟 Pi TUI**：兼容面更大，但扩大渲染与控制边界；本期不采用。

## 后果

正面：社区扩展无需改写作者接口；扩展与依赖可随 Client 统一升级、回滚；开发与发布资源选择一致；不引入新的包管理服务或 Session 权威。

成本与限制：构建端需验证标准包声明、依赖解析、可信产物与许可；SDK 升级需回归社区扩展兼容。不是所有标准扩展都能在网页完整运行，混合 Client 版本和外部环境差异仍须明确报告。

扩展拥有 Client OS 账户权限，不是沙箱。监督模式的工具审批不覆盖扩展工厂、事件或命令处理器直接访问系统；纳入受信 Release 仍意味着信任代码。

## 验证与退出条件

- 至少一个实际社区扩展在不改写为 VCPDeck API 的条件下，通过真实 SDK 和实际单文件 Release 布局完成其宣称支持的核心功能；不以 mock 或自造夹具替代社区复用验收。
- dev 与 release 从同一选择输入产生一致的资源身份、来源版本及依赖选择；只加载显式选定的 extension 资源。
- 覆盖运行时导入、工具、事件、命令及所涉及的网页交互；不支持能力明确降级或拒绝，不伪造成功。
- 缺失、篡改、资源冲突或 SDK 不兼容时明确拒绝；继续通过资源门控、执行模式、Owner/Run/项目互斥、native Pi 零污染及更新回滚验证。
- 在 Windows/Linux 支持矩阵核验所选扩展，外部条件不足时明确说明；运行行为变更同步 Current 文档及 CHANGELOG。

若需要动态安装、用户或项目资源自动发现、任意 TUI、Session 替换，或社区包要求改变 SDK 单文件发布及完整性校验边界，应另行评估并经新设计与 ADR 确认，不静默放宽本决策。
