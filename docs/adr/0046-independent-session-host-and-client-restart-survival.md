# ADR-0046：独立会话宿主与接入层存活

## 背景

现有 TerminalManager 在 Client 进程内持有真实 PTY、画面、输出序号与保留计时器。它支持连接恢复，但 Client 进程退出后原 PTY 消失，最后连接离开或 Server 断线后的有限保留也不适合长期开发。Agent 官方支持多个操作系统，不等于 VCPDeck 可以跨 Client 重启重新接入原交互现场。

ADR-0045 选择让人和自动操作者使用目标机原生 Pi TUI 与 DSH Web。维护者要求 Client 更新或重启不打断这些工作，且恢复后仍进入原活跃实例，而不是读取历史后另起 Agent。仅 detached 启动可能保住进程，却不能保证 PTY 与重新接入能力。

因此需要把工作进程与接入通道的生命周期分离，同时避免形成新的专用 Agent 管理平台。

## 决策

### 1. 独立宿主持有工作进程与 PTY

在目标机器增加通用会话宿主，独立于 Client 业务进程运行。宿主持有受管理工作进程；终端路径同时持有真实 PTY 和恢复画面所需的有界状态。Client 是可重建的控制与接入通道，不是这些资源的唯一宿主。

首期只托管经 VCPDeck 显式启动的实例。宿主提供必要的启动、列举、接入、观察、终端输入/尺寸调整及停止能力，不内嵌 Pi SDK，不解释 Agent 工具调用、模型配置、插件或对话文件格式。DSH Web 服务不因受托管而被转换成终端 UI。

优先复用现有 PTY、headless snapshot 与输出处理能力，不长期维护两套同义实现。不预先决定包名、依赖、本机运输协议或平台守护方式；这些选择须经技术验证与设计细化。

### 2. 区分接入层与进程层的存活要求

**接入层（必须满足）**：页面关闭、接入连接断开、操作者离线、Server 临时断线以及 Client 与 Server 的 Socket 重连，均不得停止受管理环境，也不得以旧 detached TTL 到期清理仍在用的工作。宿主在此场景下持续持有工作进程与 PTY。

**进程层（中断可接受）**：**Client 重启或 Release 更新导致工作进程与 PTY 被杀，是可以接受的**。维护者明确选择这一取舍，以换取不需要独立于 Client 的第二个系统级守护：不新增开机自启项，不要求宿主跨版本存活、也不要求宿主位于版本目录之外。

中断时必须满足两个不可省略的条件：

1. **如实上报**：链路、界面与审计必须体现“该实例因 Client 重启/更新而中断”，不得显示为仍在运行、不得显示为正常停止，也不得以历史恢复冒充原执行继续。
2. **提供恢复路径**：重启后能重新进入该环境并接续会话（Pi/DSH 自身的会话历史与恢复能力）。**受支持的范围仅限于会话与历史接续；被中断的那一次执行必须由使用者自行重来，系统不承诺也无法接续。**

这部分取代了早期草稿中“宿主不得位于随 Client 更新被停止的生命周期范围内”的要求。因此不再需要独立的宿主守护，也不再需要为宿主单独设计版本保留或稳定目录例外。

宿主自身崩溃、Agent 自身崩溃与机器重启同样适用上述两个条件；历史恢复不等于原执行恢复。

### 3. 宿主是运行态权威，Server 保存最小控制元数据

宿主报告真实实例、进程、PTY、画面和退出结果；Client 转发并核验，Server 保存必要身份、生命周期元数据与最小审计。数据库状态、PID 或 Agent 历史不能单独证明原进程仍在工作。

区分环境实例、Agent 对话和接入连接，沿用 ADR-0045 的原生历史归属。长期交互资源不是普通 Job；启动、停止等请求的确认也不能被解释为 Agent 对话已经完成。

终端画面和输出默认仅在目标机有界内存中维护，不因新增宿主引入永久录屏或 Server 正文镜像。中央 Pi 读取内容后的数据边界按 ADR-0045 处理。

### 4. 重连先对账，不盲目重建或重发

接入层重连（Socket 重连、页面重新打开）后，先认证并查询宿主，核验已有受管理实例，再向 Server 对账和恢复接入。区分 Client 连接代次、宿主运行身份与环境实例身份。

**进程层重启（Client 重启/更新）后**，宿主与实例已不存在：必须据实将旧实例标为**因重启中断**，不创建替代进程伪装原实例继续运行，并向使用者指出“可重新开始 / 可恢复会话”，而不是把新实例描述为原执行继续。

宿主暂时不可达或不完整报告表示状态尚未确认，不能仅据一次空报告将旧实例全部标为已退出或要求关闭。确认资源退出后据实展示中断，不创建替代进程伪装原实例继续运行。

启动、输入或停止确认丢失时先查询、观察和核验，不重复提交可能已经执行的操作。稳定实例关联必须防止误认复用 PID、旧连接或迟到响应；具体标识和幂等查询协议由技术设计确定。

重新接入取得一致序列基线的快照与后续输出；允许有界回放和显式重新同步，不要求保存断线期间无限输出。慢消费者不能阻塞远端工作或其他观察者。

### 5. 控制、取消、停止与删除分开

人工直接使用不依赖中央 Pi。Pi 受管理输入与 resize 经协调通道强制单写，旧操作者失去控制权后不能继续写入；重连不能仅凭旧连接状态恢复自动输入，须重新核验权限与现场。

人工接管停止自动输入，不自动取消应用当前执行。DSH 原生 Web 只协调受管理自动操作者，不宣称覆盖所有页面/API 的强制全局输入锁。

停止自动输入、取消应用当前执行、停止环境进程及删除历史是四种不同操作。显式停止以宿主可确认的结果为准，超时展示结果不明，不默认删除历史，也不宣称撤销工作进程已产生的系统副作用或必然清理主动脱离托管边界的所有进程。

### 6. 本机接口认证与运行账户

宿主只提供受认证、受 OS 访问限制的本机接口，不增加公网控制端口，不提供 Client 到 Client 的直接控制链路。远程操作仍经过 Server 身份与业务控制；loopback 本身不是身份认证。

启动参数、环境变量、路径、屏幕、网页 token 与 Agent 凭据均按敏感数据处理；跨边界输入严格校验，未知动作、字段或不兼容版本明确拒绝。协议不兼容只禁用相关接入能力，不通过重启宿主、杀工作进程或回退旧 Pi 模式掩盖问题。

实例使用 **Client 系统级账户**（Windows SYSTEM / Linux root 等价专用账户）和选定项目目录，沿用 [ADR-0027](./0027-system-level-client-installation-and-clean-migration.md) 的现有系统部署，**不引入跨账户启动、每用户宿主或用户凭据代持**。Agent 自身配置与凭据位于该账户下，不使用人类用户的个人主目录配置（与 [ADR-0045](./0045-central-pi-and-native-agent-environments.md) 决策 2 一致）。

该选择意味着宿主与 Agent 均具整机最高权限。因此本机接口的 ACL、token 文件权限与实例身份校验属于**安全边界**，不是可选的加固项；未验证本机隔离前，不得声称已完成隔离。

## 与既有决策的适用关系

- **ADR-0007**：对新宿主管理的环境，局部替代 Client 进程独占 PTY/Worker 与“Client 重启即资源消失”的边界。真实资源仍在目标机器，Server 最小持久化和界面非权威原则保留；未迁移的旧 Terminal/Pi 仍按旧实现运行。
- **ADR-0003**：保留 Launcher 管理业务更新与回退的职责，本 ADR 不改变其现有冻结状态，也不决定由 Launcher 或系统守护启动宿主。新生命周期分离必须在实际更新和进程清理链路中验证。
- **ADR-0027**：宿主与 Agent 直接沿用其现有系统级部署与运行账户（Windows SYSTEM / Linux root 等价专用账户），不引入跨账户启动。系统守护与进程清理仍需验证不杀宿主。
- **ADR-0045**：本 ADR 补充其原生 Agent 路径的保活与运行态权威，不扩展为 Agent 配置、插件或对话管理服务。

本次不修改旧 ADR 状态或 Current 文档。实施迁移时明确新旧路径适用范围，并同步协议、兼容、部署、运维、测试和 CHANGELOG，不将已批准方向写成当前能力。

## 候选方案

1. **继续由 Client 托管 PTY，只延长 TTL**：可解决部分页面断线，但 Client 重启仍丢失资源；不能满足需求。
2. **detached 启动或从 Session 历史重新启动**：前者不保证终端重接入，后者不是原活跃执行；不采用为保活保证。
3. **按平台直接依赖 tmux/screen 与系统服务**：可减少部分自研，但需要核验 Windows 等价能力与跨平台接入边界，不能直接保证统一行为；不将其锁定为基础方案。
4. **独立通用会话宿主**：采用生命周期与职责边界；具体实现仍优先复用现有代码、标准能力和已安装依赖，不提前造通用 Agent 平台。
5. **将交互进程移到 Server**：无法保持目标机器原生环境，扩大远端文件和凭据处理责任；不采用。

## 后果

正面：Client 接入与工作现场解耦，人工和 Agent 可持续使用同一现场，真实资源权威明确；新增组件不绑定 Pi/DSH 特定 SDK 或配置协议；不需要第二个系统级守护，部署面明显变小。

成本与限制：增加一个需部署、认证与资源限制的运行组件。**已明确接受的代价：Client 重启或更新会中断正在执行的工作**，受支持的范围只有会话与历史接续；被打断的那一次执行必须重来。宿主自身失败同样导致活动终端不可恢复，必须据实报告而不能伪装。

支持目标为 **Windows 与 Linux**；macOS 不支持，不计入验收、不预留实现分叉。真实 PTY、系统进程清理与多平台依赖可行必须分别在两平台验证。未验证平台明确标记，不以 Agent 自身支持该平台替代保活测试。

## 验证与退出条件

- Windows 与 Linux 分别启动原生 Pi TUI 和 DSH Web；人工可用，运行账户为 Client 系统级账户，项目目录符合选择。
- Client 重启及真实 Release 更新后：旧实例被如实标为**因重启中断**，不显示为仍在运行或正常停止，也不创建替代进程伪装恢复。
- 重启后可通过 Pi/DSH 自身的会话历史接续对话；界面明确提示“被打断的执行需要重做”。
- 页面/Server 断线超过旧 30 分钟保留窗口，环境仍存活；恢复不依赖无限输出回放。
- 实际 Launcher/系统守护/进程树清理行为与上述语义一致：**允许杀宿主，但必须上报中断、不得伪装**。
- 覆盖宿主不可达、报告不完整、确认退出、PID 复用、迟到事件及启动/输入/停止响应丢失，不伪装恢复、不误杀、不盲目重发。
- 快照与增量序列一致，缓冲有界，慢消费者隔离；接管后旧输入/resize 被拒绝，自动操作者恢复前重新观察。
- 未认证本机调用、无效远程身份、未知协议输入和不兼容版本被拒绝；日志、错误和审计无敏感材料泄露。
- 显式停止仅作用于已确认的受管理实例，保留历史；宿主/机器重启后不能将新实例描述为原执行延续。

若未来要求宿主跨 Client 版本存活、跨机器迁移、永久终端录屏或新增公网宿主接口，须重新评估并另立 ADR。
