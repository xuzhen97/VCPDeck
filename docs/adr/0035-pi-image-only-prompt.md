# ADR-0035：Pi Prompt 允许空文本与有效图片组合

- 状态：Accepted
- 日期：2026-09-27
- 决策者：项目维护者
- 关联：[ADR-0007](./0007-client-owned-interactive-runtime.md)、[ADR-0008](./0008-pi-session-job-and-run-lifecycle.md)、[ADR-0034](./0034-pi-session-execution-mode-override.md)、[`docs/protocols.md`](../protocols.md)

## 背景

Agent Chat 现有图片上传可获得短期附件引用，但输入框只允许有文字时发送，Server 也拒绝空文本 Prompt。用户需要粘贴并直接发送图片，而不是由界面偷偷插入“请看图片”等提示词。Prompt 从 Browser 经 Server、Shared 协议和 Client Worker 进入 Pi SDK；只在前端放宽会造成客户端与服务端语义不一致，甚至先接纳无效 Run。

## 决策

1. `prompt` 保持字符串类型。**空文本或仅空白的 Prompt 仅在至少一张有效图片随请求提交时合法**；无文本且无有效图片必须拒绝。不得通过隐藏占位文本伪造用户输入。图文混合与纯文本维持原有含义。
2. Server 在创建 Run 和发布事件之前严格校验请求组合、附件数量与引用有效性；继续执行 Owner、项目及运行状态授权。Shared 的 Server → Client `agent.prompt` 解析器也校验相同组合，Client 在跨信任边界再次验证，不假定 Server 已校验就接受无内容请求。
3. 纯图片输入沿用现有临时附件引用、Server 控制面与 Client 下载/解码路径；真实图片和对话正文由 Client/Pi Session 管理。Server 的 Job、普通日志和数据库不新增正文或图片内容，SSE 仍只是投影。
4. 必须确认当前受支持 Pi SDK 能把 `prompt("", { images })` 作为真正的图片消息发送并写入可回放的 Session 历史。**若实际 SDK 不支持，停止纯图片能力实施并重新评估决策**，不得静默改成自动补词。
5. 组合校验属于跨端协议语义：Server/Client 的版本与能力必须明确匹配；若旧 Client 不安全支持新语义，升级协议版本并按 ADR-0008 的精确匹配规则拒绝混用，不允许仅靠 UI 隐藏不兼容性。线格式和具体版本号在实现时由 Shared 契约与兼容性测试确定。
6. 粘贴、附件预览和图标化布局是表现层行为，不改变上述数据权威、Owner/Observer 权限、图片类型与容量上限。

## 候选方案

- **自动补一段提示词以绕过空文本校验**：实现较少，但模型收到的正文不是用户输入，历史记录也失真，因此不采用。
- **只放宽前端发送按钮**：Server 拒绝空文本，无法端到端工作；也不能构成可信协议边界，不采用。
- **允许任意空 Prompt**：会制造无内容 Run 并消耗项目锁与模型资源，不采用。

## 后果

- 可在不更改正文权威的前提下提交纯图片消息；空请求仍 fail closed。
- Shared、SDK、Server、Client、Frontend 和兼容门控必须同步审查并回归；旧客户端若无法正确处理纯图须明确升级或拒绝。
- 需要验证附件引用的有效性、上传完成状态、过期与边界拒绝，避免无效请求占用 Run；前端不得把“上传中/失败”误当成可发送图片。

## 验证与退出条件

测试纯图片、图文混合、纯文本、空文本无图、空白文本无图、非法/过期附件和超限输入；确认无效请求在 Run 接纳前拒绝、Observer 不能发送、Client 协议解析同样拒绝；验证真实 Pi SDK 的空文本图片消息与历史回放、日志/Job 无正文。若 SDK 行为、协议兼容性或图片数据权威发生变化，重新评估本决策。
