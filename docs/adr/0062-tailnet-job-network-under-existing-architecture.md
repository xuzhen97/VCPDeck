# ADR-0062：沿用现有架构管理 Tailnet，供指定 Job 访问私网

- 状态：Accepted（代码已实现并通过自动测试；Windows/Linux 真机安装与入网验收尚未执行）
- 日期：2026-11-11
- 决策者：项目维护者
- 关联：[ADR-0004](./0004-typed-job-kernel.md)、[ADR-0005](./0005-shared-contracts-and-communication-channels.md)、[ADR-0009](./0009-trusted-operator-security-domain.md)、[ADR-0038](./0038-git-ssh-distribution-under-shared-psk.md)、[ADR-0053](./0053-retire-p2p-tunnel-and-browser-remote-desktop.md)、[ADR-0055](./0055-client-operator-annotations.md)、[ADR-0060](./0060-retire-rds-consolidate-a2a.md)

## 背景

维护者需要通过 VCPDeck 使选定的 Windows/Linux 机器加入 Tailnet，并让某些现有命令或脚本 Job 使用私网地址访问业务服务；明确不希望改变现有通信架构。首版选择手动导入 Auth key、检测并按需安装官方 Tailscale，以及提供必要的机器网络摘要。

这需要明确第三方网络软件、凭据保护和观测信息的长期边界，防止把局部组网需求扩展为新的通用隧道、全局选路或控制面替换。本决策补充既有能力，不替代上述 ADR，也不恢复已退役的 WebRTC、浏览器远程桌面或会话级隧道。

## 决策

1. **官方 Tailscale 提供操作系统私网。** VCPDeck 只负责必要的管理与观测。Server 派发、Client 执行、Job 状态和结果回传继续沿用现有链路；Files、Storage、Terminal、FRP 的协议和数据路径不变。需要持久化、取消、恢复或审计的安装与入网操作复用 Typed Job 生命周期，不另建执行平台。
2. **首版手动导入密钥并按需安装。** Server 保存操作者提供的 Auth key，不接 OAuth 自动签发或远端密钥撤销。Windows/Linux 通过明确操作检测并按需安装官方 Tailscale；已有安装复用，不自动升级、卸载、切换已登录网络或强制重新认证。不默认启用 Exit Node、子网路由或 Tailscale SSH，不擅改已有 DNS/路由配置。安装支持范围须经平台验证，不承诺所有 Linux 环境均支持。
3. **密钥正文不进入普通任务持久化与输出。** Server 加密保存密钥，解密根密钥与密文分离；普通接口只返回非秘密元数据和脱敏摘要。入网经既有认证链路向具体操作与执行目标交付敏感输入，Job 持久化载荷只引用凭据记录。正文不得拼入普通 exec 命令、进程命令行、Job 载荷/结果、日志或注解；Client 使用受权限保护的临时凭据并在各终止路径清理。旧 Client 不支持时拒绝操作，不降级为明文 exec。
4. **保持当前可信操作者和共享 PSK 模型并据实披露限制。** Client ID、当前连接与操作绑定是运维关联，不构成密码学每机身份或密钥防冒领保证；高权限或已失陷主机也不在保密隔离承诺内。发生 PSK 或密钥疑似泄漏时，应在 Tailscale 侧撤销相关密钥、审查并移除非授权设备，按影响范围轮换凭据与 PSK；仅删除 VCPDeck 记录或撤销 Auth key 均不能证明已入网设备退网。
5. **网络摘要与操作者注解分离。** Client 只报告必要的本机安装、服务、登录、地址与观测时间，Server 保存并提供给机器详情及 CLI/SDK。未知、未报告与离线历史观测不能显示为实时已入网；不上传完整 peer 列表或原始诊断正文。该摘要不覆盖人工公网地址注解，不参与授权，也不证明任意来源到业务端口可达。密钥有效期、可复用性等操作者声明须区别于可靠观测，未知就保持未知。
6. **指定 Job 显式访问 Tailnet 地址。** 操作者或 Agent 在现有命令/脚本中使用目标私网地址，并按业务协议验证服务与身份。要求私网的脚本失败时不得自动替换为公网目标。首版不增加通用 Job 网络模式、全局端点优选或每 Job 网络隔离；Tailnet 也不保证物理直连，可能使用中继。Server 不参与私网业务请求时，不必仅为派发 Job 入网。

## 候选方案

- **仅由操作者在机器上手工组网**：不涉及受管凭据，但不能满足已确认的集中导入、按需安装和机器信息展示需求。
- **OAuth 自动签发并建设完整 Tailnet 控制台**：自动化程度更高，但超出首版手动导入的选择，暂不采用。
- **替换控制/文件通道或恢复通用隧道**：与维护者不改变现有架构的要求相悖，不采用。
- **将自动观测塞入人工注解，或用普通 exec 明文传 key**：分别破坏数据来源语义和密钥保护边界，不采用。
- **先重构每机认证再接入**：可改善身份边界，但超出当前可信机器部署范围，不作为本需求前置条件；不得因此隐瞒共享 PSK 风险。

## 后果

- 可在保持现有通信架构的前提下，管理官方组网软件并让指定 Job 使用私网服务；FRP 继续承担既有端口暴露职责。
- 必要的凭据、管理操作及可选网络摘要涉及 Shared、Server、Client、SDK/CLI/前端契约增量，必须同步校验、兼容性和测试，不能以“不改架构”为由省略边界检查或重构无关列表协议。
- 需要维护受支持平台、安装材料可信来源、凭据根密钥备份恢复与临时文件清理。安装或登录的系统副作用不随 Job 取消自动撤销，必须报告实际阶段，不虚报回滚。
- 一次性 key 不得批量复用；结果不明时不得自动恢复为可安全重用。手动导入不保证能提前验证提供方有效性。
- 服务监听、防火墙、Tailnet 策略和名称解析仍影响可用性；本功能不自动修改目标业务服务配置，也不保证浏览器或未入网调用方可访问私网。

## 验证与退出条件

- 自动测试覆盖密钥不回显/不落普通 Job 与日志、执行绑定、临时文件清理、一次性 key 并发与不明结果、旧 Client 拒绝和网络摘要未知/过期语义。
- 安装和登录分支验证已有配置不被覆盖，失败、待审批、取消、超时与断连如实报告。
- 另行授权后，在受支持 Windows/Linux 实机验证按需安装入网、CLI/SDK/界面可查摘要、现有 Job 经 Tailnet 访问业务服务；私网访问失败不回退公网，原有控制与其他业务链路无回归。未实施或未验收时不得宣称能力已可用。
- 若出现不受信机器、强每机授权或隔离、自动选路、OAuth 管理或变更既有数据通道的明确需求，应另立决策，不静默扩展本 ADR。
