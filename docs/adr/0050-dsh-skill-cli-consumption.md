# ADR-0050：DSH 通过轻量技能插件消费 VCPDeck 基础能力

- 状态：Accepted
- 日期：2026-10-13
- 决策者：项目维护者
- 实施状态：尚未实施；设计批准不代表插件已交付或安装验收通过。
- 关联：[ADR-0001](./0001-control-plane-and-outbound-clients.md)、[ADR-0017](./0017-cli-multi-environment-configuration.md)、[ADR-0049](./0049-retire-pi-dsh-integrations-and-focus-on-core-capabilities.md)

## 背景

VCPDeck 已提供通用 CLI、Pi Skill 和 VCP 工具桥。维护者希望 DSH 用户也能安装技能入口并调用基础能力，同时避免再次引入 Agent 托管、专用运行协议和独立发布链。

ADR-0049 保留通用调用入口，但不默认授权新增适配面。本决策明确批准 DSH 的轻量消费入口；不替代 ADR-0049，也不恢复其退役体系。

## 决策

1. **采用 Host-only bundle + Skill provider**：DSH 插件仅注册用户与模型均可调用的 `vcpdeck` 技能，提供实际安装资源目录及随包 CLI 的绝对路径，并遵循宿主注册与释放生命周期。不向用户技能目录复制或同步文件。
2. **复用同一业务入口**：Pi 与 DSH 共用宿主中立的技能正文及预构建 CLI，调用链保持 CLI → SDK → Server → Client。插件不复制 HTTP、认证、轮询或业务状态机，不绕过 Server 控制面。
3. **沿用同仓库、同版本 Tag 交付**：固定 GitHub Tag 的安装构件携带完整入口、patch、技能及预构建 CLI。安装端不构建工作区，不靠 `prepare`、`postinstall` 或运行时下载补齐构件；适配入口使用 ESM 与 Node.js 标准库，不引入 DSH 核心运行时包依赖。仓库根包安装和打包行为必须实测，入口零依赖不替代交付验证。
4. **环境与授权边界不变**：执行 CLI 保持宿主当前任务工作目录，沿用 CLI 的环境选择和凭据环境变量，不新增宿主专属业务配置或秘密存储。宿主工具审批策略不替代具体业务操作授权；既有写操作确认、身份校验、敏感信息保护和权威终态核验规则保持有效。
5. **不恢复 Agent 管理体系**：不新增聊天、Run、会话托管、Profile、模型或凭据管理、session-host、DSH 启动与代理。首版不新增原生工具、MCP server 或客户端界面；后续扩大消费形态需独立设计与授权。

## 候选方案

- **安装时复制技能到用户目录**：需要处理覆盖冲突、同步记账和卸载清理，扩大宿主全局文件维护责任，不采用。
- **独立插件包或仓库**：形成第二套技能、CLI 与版本同步及发布流程，当前收益不足，不采用。
- **直接暴露 DSH 原生工具或技能加工具组合**：需要新增工具参数、执行和错误契约，不符合首版最小复用目标，不采用。
- **同仓库 bundle 注册共用 Skill + CLI**：复用现有业务与发布边界，采用。

## 后果

正面：DSH 获得统一能力入口，业务权威和安全规则不变，不为宿主生态增加 Server/Client 运行组件。

成本与约束：需要维护 DSH 注册契约、包元数据和安装验收；CLI 执行环境须具备 Node.js 24+，凭据环境变量须对执行进程可见。不能假定 Electron 的可执行文件等于独立 Node，也不新增自动下载或运行环境修复逻辑。

运维：插件升级可能要求重启或新会话，必须区分保存状态、实际激活状态与会话菜单缓存；构件缺失明确失败，不静默换用其他 CLI。

本决策只批准架构方向。实施、实际 profile 安装、正式发布、创建 Tag 或远程副作用均须取得对应授权；旧 ADR 的状态维护不隐含在本决策中。

## 验证与退出条件

- bundle 声明、入口、技能元数据、资源路径和生命周期释放正确；含空格安装路径可调用。
- 固定版本构件包含技能与预构建 CLI，安装无需构建工作区或批准插件安装脚本；本地加载不能替代 GitHub 分发验证。
- DSH 能加载技能并在当前任务工作目录运行 CLI；业务只读验收在具备独立授权的测试环境和凭据时进行，未验证项明确报告。
- Pi 既有技能与 CLI 调用约定、VCP 工具桥及基础业务能力不受破坏；相关测试、构建和文档同步完成。
- 若后续引入专用运行组件、独立认证配置或新的业务调用契约，重新评估并另立决策，不借本 ADR 扩大范围。
