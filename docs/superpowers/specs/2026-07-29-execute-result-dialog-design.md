# 远程执行结果弹框设计

## 目标

优化机器详情“执行”页：移除长期占据右侧空间的结果卡片，使执行表单使用完整内容宽度；提交任务后立即打开弹框，用明确动画反馈任务正在创建或等待，完成后在原位展示执行结果。

## 交互设计

1. 用户填写命令或脚本并提交。
2. 立即打开“执行任务”弹框。
3. `creating` 阶段显示旋转加载图标和“正在创建任务…”。
4. `waiting` 阶段显示相同动画和“命令已下发，正在等待机器返回结果…”。
5. `complete` 阶段停止动画，展示任务状态、Job ID、退出码、耗时、错误码和错误说明。
6. `error` 阶段展示“无法创建或等待任务”，并允许关闭。
7. 关闭弹框只隐藏本次进度或结果，不取消已经下发的远程任务。
8. 下一次提交会重新打开弹框并清空上一次结果。

## 页面布局

- 删除右侧“执行结果”卡片。
- “远程执行”卡片占满可用宽度。
- 保留命令/脚本 Tab 和现有字段，不改变任务 payload 或后端协议。
- 执行按钮在任务进行中禁用，并显示旋转图标和“执行中…”。
- 弹框使用现有 Radix Dialog 组件，支持焦点管理、Esc 关闭和遮罩层。

## 数据流与边界

继续复用 `useJobAction`：

- `run()` 创建任务并等待最终状态。
- 页面根据 `phase` 渲染弹框内容，不增加新的轮询或状态层。
- 不展示 Server 尚未持久化的过程输出，也不伪造实时终端效果。
- 不新增取消按钮；关闭弹框不调用取消接口。

## 错误处理

- 创建或等待失败时在弹框内使用 `role="alert"` 展示稳定错误提示。
- Job 返回业务错误时展示 `errorCode` 和安全的 `errorMessage`。
- 若任务完成但缺少退出码或耗时，相应字段不渲染。

## 验证

自动化测试覆盖：

- 页面不再渲染右侧结果卡片。
- 提交后立即出现带执行动画的模态弹框。
- 等待完成后同一弹框展示退出码和耗时。
- 脚本 payload 保持不变。
- 错误状态在弹框中显示。
- 关闭弹框不会调用任务取消接口。

通过 Frontend 测试、TypeScript/Vite 构建、LSP/diagnostics 和 Playwright 实际交互验证。
