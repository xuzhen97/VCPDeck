# 文件上传成功提示与任务通知美化设计

## 背景

文件页当前会在上传成功后显示一条绿色提示，但提示无法手动关闭。右上角任务通知可以展示进行中和已完成任务，但当前面板层次、状态识别和操作密度较弱，需要在不改变任务轮询与下载行为的前提下提升可读性。

## 目标

- 文件上传成功提示支持通过 X 关闭。
- 关闭成功提示只影响当前 `FilesPanel` 挂载会话，不写入本地存储，也不影响导入结果。
- 美化右上角任务通知面板，提升状态层次、扫描效率和操作可达性。
- 保持现有任务轮询、下载、失败信息与清除逻辑不变。
- 不增加依赖，不修改 API、数据库或共享协议。

## 交互设计

### 文件页上传成功提示

- 成功状态显示成功图标、“上传完成”语义和文件名。
- 右侧提供独立的 X 关闭按钮。
- 关闭按钮的可操作区域至少为 44×44px，并提供 `aria-label="关闭上传提示"`。
- 点击关闭只执行 `setUploadState(null)`。
- 上传中状态继续显示进度条；失败状态继续使用 `role="alert"`，不改变现有错误处理。

### 任务通知

- 铃铛仍是任务通知的唯一入口，进行中任务数量角标保留。
- 面板宽度约 360px，并设置最大高度和内部滚动，避免大量通知撑开页面。
- 面板顶部显示标题、铃铛图标和当前进行中任务数量。
- 进行中任务和终态任务分别显示为“进行中”和“最近结果”分组。
- 每条任务使用一致的状态图标：进行中使用加载/进度语义，成功使用成功图标，失败使用警告图标，取消使用取消图标。
- 进行中任务保留阶段文字、进度条和字节数；导出上传完成但云盘仍在保存时继续显示收尾状态。
- 完成项保留“下载”文字按钮。
- “清除”改为紧凑的图标按钮，仍保留包含任务 ID 的无障碍名称。
- 无任务时显示清晰的空状态。

## 视觉规范

- 延续现有 VCPDeck 淡色/深色玻璃面板风格、圆角和边框层次。
- 使用现有主题语义色：`primary`、成功色和 `destructive`；不在组件中引入新的原始色值。
- 使用 `lucide-react` 图标，不使用 emoji 或新增图标依赖。
- 面板和条目使用轻量边框、背景层级和阴影，避免大面积渐变。
- 交互过渡只使用 opacity/transform，约 150–200ms；尊重 `prefers-reduced-motion`。
- 所有图标按钮保留清晰的焦点环、悬停/按下反馈和无障碍名称。

## 实现边界

### `packages/frontend/src/pages/files-panel.tsx`

- 增加成功提示关闭处理。
- 调整上传状态条 JSX 与 Tailwind class。
- 不拆出单独组件，避免为一次性展示增加抽象。

### `packages/frontend/src/components/notification-bell.tsx`

- 保留轮询、状态识别、下载和清除逻辑。
- 只调整展示结构、图标、分组和面板样式。
- 从已有 `active` 与 `finished` 状态派生分组，不增加新的状态管理。

### `packages/frontend/src/styles.css`

- 优先使用现有 Tailwind class。
- 只有在组件 class 无法表达且确有必要时，才增加通知入场或减少动效规则。

## 验证方案

1. 在 `files-panel.test.tsx` 增加测试：导入完成后显示成功提示，点击“关闭上传提示”后提示消失。
2. 在 `notification-bell.test.tsx` 增加展示断言：面板显示分组标题，清除按钮具有任务 ID 无障碍名称；已有下载和清除行为测试继续通过。
3. 运行前端定向 Vitest 测试。
4. 运行 `pnpm --filter @vcpdeck/frontend build`。
5. 运行 `lens_diagnostics` 检查编辑文件的阻塞错误。
6. 运行 GitNexus `detect_changes`，确认变更只涉及文件面板、通知组件、相关测试及必要样式。

## 非目标

- 不修改任务轮询间隔。
- 不增加通知持久化、跨页面同步或全局消息中心。
- 不改变导入成功、失败、冲突覆盖和下载的业务语义。
- 不修改后端、SDK、数据库或共享协议。
