# Job 执行内容展示设计

## 目标

在任务详情右侧抽屉中展示远程执行 Job 实际执行的命令或脚本，便于审计和排查问题，同时避免直接渲染完整原始 payload。

## 数据来源

Server 创建 Job 时已经将执行请求保存到 `Job.payload`，无需修改数据库、Server 接口或 SDK：

- 命令模式：`mode`、`command`，以及可选的 `cwd`、`timeout`
- 脚本模式：`mode`、`executable`、`args`、`script`，以及可选的 `cwd`、`timeout`

Frontend 只读取 `type === "exec"` 的已知字段，不序列化或展示整个 payload。

## 详情展示

### 命令模式

在任务元数据之后增加“执行内容”区域：

- 使用等宽代码区完整展示 `command`
- 保留换行
- 长内容在代码区内部滚动
- 有值时显示工作目录和超时时间

### 脚本模式

展示以下元数据：

- 解释器
- 参数
- 工作目录（如有）
- 超时时间（如有）
- 脚本行数

脚本正文使用原生 `<details>/<summary>`：

- 默认折叠
- 点击“查看脚本”展开
- 展开后可再次收起
- 依赖浏览器原生键盘与可访问性行为，不增加 React 状态
- 正文使用等宽代码区，保留换行并限制最大高度

## 滚动模型

现有 `Drawer` 使用 `h-full overflow-y-auto`，继续负责整个任务详情的纵向滚动。

命令和脚本代码区使用独立的最大高度与 `overflow-auto`，负责特别长内容的局部滚动。展开长脚本不会把抽屉撑出视口。

## 安全边界

- 不展示原始 payload JSON
- 只对白名单字段进行类型检查后展示
- 不展示 payload 中未知的 `password`、`secret`、`token` 等字段
- stdout 和 stderr 保持现有按需展示行为
- 历史 Job 缺少字段或 payload 格式异常时，不报错，只省略对应区域

## 测试

在现有任务页测试中覆盖：

1. 命令 Job 的详情展示完整命令。
2. 脚本 Job 展示解释器、参数和脚本行数。
3. 脚本正文默认不可见。
4. 点击“查看脚本”后正文可见，并可收起。
5. payload 中未列入白名单的敏感字段不会出现在详情中。
6. 现有任务表格、详情抽屉、stdout 和 stderr 行为保持正常。

## 范围外

- 不增加 payload 脱敏框架或通用 JSON 查看器
- 不修改 Job 持久化结构
- 不修改远程执行协议
- 不增加代码高亮依赖
- 不增加独立脚本弹框
