# 文档归档规则

> 维护责任：项目维护者｜最后核验：2026-08-15

本目录用于保存已失效但仍有明确历史价值的材料。归档不代表继续维护，也不能作为当前实现依据；完整文档生命周期见 [`../documentation-governance.md`](../documentation-governance.md)。

## 应归档的内容

- 曾正式采用、后来被替代的重要设计；
- 被拒绝但将来可能重复讨论的重要方案；
- 重大迁移、事故或兼容演进背景；
- 对理解历史版本仍有独立价值的材料。

一次性实施步骤、文件清单、调试过程、AI 推理和已被长期文档完整承接的重复说明应直接删除，不因“以后可能有用”而归档。

## 归档步骤

1. 在原文顶部加 `Archived` 或 `Superseded by ...`；
2. 说明归档日期、原因、替代文档；
3. 移入 `docs/archive/<year>/` 时修复入站链接；
4. 从 `docs/design/README.md` 的当前索引移除；
5. 不修改历史结论，只补充归档元数据；
6. 将仍有效的当前事实、长期决策和未完成事项分别迁移到 Current 文档、ADR 和 Roadmap/Issue；
7. 确认没有 Current 文档继续把归档材料作为唯一事实来源。

## 命名

```text
docs/archive/YYYY/YYYY-MM-DD-title.md
```

## 禁止事项

- 不因文档过时而静默删除决策历史；
- 不让 Archived 文档继续作为 README 或 Current 文档的唯一链接；
- 不把未来计划、验证结果和当前能力混写；
- 不在归档文档上持续追加现行设计。
