# 0.22.2 验证记录：明文 HTTP 下「Agent 任务」页恢复

> 日期：2026-10-22｜版本：`0.22.2`｜环境：本地明文 HTTP 冒烟 + 线上 prod

## 1. 背景

线上驾驶台（`http://118.89.196.44:3001`，**明文 HTTP**）打开「Agent 任务」（`/agent-tasks`）只显示「无法加载 Agent 任务」，服务端一切正常。

排查顺序与证据：

| 探针 | 结果 | 结论 |
| --- | --- | --- |
| 页面内直接 `POST /api/a2a`（`ListTasks`） | `201`，任务数据完整 | 后端无责 |
| 页面 `isSecureContext` / `typeof crypto.randomUUID` | `false` / `"undefined"` | 命中非安全上下文 |
| 线上 bundle 片段 | `function dN(e,t=()=>crypto.randomUUID()){…}` | 前端裸调用 |
| SDK `tasks.ts` 默认 `nextId` | `() => crypto.randomUUID()` | 请求发出前即抛 `TypeError` |

`crypto.randomUUID` 只在安全上下文（HTTPS / localhost）存在；线上是 `http://<IP>:3001`，因此该页**请求还没发出**就抛 `TypeError`，`ErrorState` 只呈现固定文案「无法加载 Agent 任务」，把真实异常吞掉了。本地 dev 跑 `localhost` 属安全上下文，所以 0.22.0 验收时不可能复现。

## 2. 修复内容（`df102fd`）

- 新增 `packages/sdk/src/uuid.ts`：优先 `crypto.randomUUID`，缺失时退回 `crypto.getRandomValues`（非安全上下文可用）按 UUID v4 规则拼装，与前端既有 `lib/utils.randomUUID` 同策略。
- `packages/sdk/src/tasks.ts`：`createTasksApi` 的默认 `nextId` 改用该函数，签名与 JSON-RPC 行为不变。
- 回归测试：`uuid.test.ts` 覆盖两种上下文；`tasks.test.ts` 新增「无 `crypto.randomUUID` 时 `list` 仍能发出请求」。

影响面：`createTasksApi` 仅由 `VcpDeckClient` 构造函数与测试调用（GitNexus 索引未收录该符号，按调用链读码确认），改动为默认参数内部实现。

## 5. 已知偏移

- `ErrorState` 仍只显示固定文案，会吞掉真实异常；本次未改，后续应把错误摘要透出到界面，降低同类排障成本。
- 同类风险不止 `crypto.randomUUID`：`crypto.subtle`、`navigator.clipboard`、`serviceWorker` 等也在非安全上下文不可用，新增前端代码时需逐个做特性检测。
