## 3. A2A 取消

派发长任务 `task_e37369d1a9cb4a92`（要求每 10 秒输出一次、共 12 次），在 `/agent-tasks` 详情抽屉操作：

1. 点「取消任务」→ 进入确认态（出现「放弃」/「确认取消」），此时**未**发出 `CancelTask`；
2. 点「确认取消」→ 4 秒内 `GetTask` 返回 `TASK_STATE_CANCELED`；
3. 事件链尾记录 `#132 task.canceled [acp]`；
4. 抽屉刷新为「已取消」，取消按钮消失。

UI 与服务端走同一条 `CancelTask`，`vcpdeck tasks cancel` 是同一路径。

## 4. 界面可见性

`/agent-tasks`（侧栏「Agent 任务」）用 `ListTasks` 分页展示（状态 / 目标 agent / 意图 / 产物数 / 更新时间），详情抽屉展示 `GetTask` 的 history、artifact 元数据与 `/api/tasks/:id/events` 时间线。与「任务」页的 Typed Job 是两套模型，页面上明确区分。

## 5. FRP 承载端口暴露

- 建映射：`POST /api/frp/mappings`（`localPort=3001` → `remotePort=17055`，测试 frps 端口池 `17001-17100`）；
- 可达：`GET http://127.0.0.1:17055/api/health` 返回 Client 侧服务响应 `{"ok":true}`；
- 删除：`DELETE /api/frp/mappings/<id>` 后该端口立即不可达；
- 删除最后一条映射后 `~/.vcpdeck/frp/frpc-combined.toml` 被写成空配置（无残留 proxy 块）。

失败可见性：`remotePort=39999` 越界返回 `400 FRP_PORT_OUT_OF_RANGE` 与「端口 39999 超出实例配置范围 17001-17100」，不再退化为笼统 `500 FRP 操作失败`。

probe 计数：frps 会保留已断开 frpc 的统计条目（`conf: null`、`lastCloseTime` 有值、端口已释放），`proxies.offline` 因此累加；判断实际隧道看 `online` 与数据库记录。
